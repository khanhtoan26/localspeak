# Phase 02 - UI Design Contract

> Visual and interaction contract for Phase 02: JSON Input & Pronunciation/Fluency Metrics.

---

## Scope Lock

Phase 02 implements **JSON mode and deterministic metrics only**.

### In Scope

- Paste speech assessment JSON as the primary input path.
- Upload a `.json` file as the secondary input path.
- One-click load of canonical sample JSON from `.artifacts/speech-response.json`.
- Backend-owned validation preview.
- Manual deterministic analysis through the primary `Analyze JSON` action.
- Friendly validation and warning display.
- Deterministic pronunciation and fluency result cards.
- Lightweight result tabs: `Summary`, `Words`, `Phonemes`, `Pauses`.

### Out of Scope / Deferred

- Gemini-generated feedback.
- Audio upload, microphone recording, streaming analysis, fillers, stress, rhythm, and intonation.
- Supabase auth, saved history, and previous-session browsing.
- Full dashboard visuals, timeline charts, IELTS Analysis tab, and long-term progress views.
- Any UI copy implying that feedback is generated by Gemini or by a human IELTS examiner.

## Spacing Scale

Declared values must remain multiples of 4 except explicitly listed accessibility exceptions.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge gaps, JSON path/value separators |
| sm | 8px | Compact element spacing, tab internal gaps, helper text spacing |
| md | 16px | Default card padding, default stack gap, form field spacing |
| lg | 24px | Page padding on desktop/tablet, major card groups, input/result separation |
| xl | 32px | Header-to-content separation, result section top margin |
| 2xl | 48px | Major page section breaks on desktop |
| 3xl | 64px | Reserved for future dashboard-level spacing; do not use heavily in Phase 02 |

Exceptions:

- Interactive controls must have a minimum hit target of `44px` height or width.
- Primary and secondary buttons use `min-height: 44px`.
- File input visible trigger uses `min-height: 44px`.
- Textarea minimum height is `220px` on mobile and `280px` on tablet/desktop.
- Card border radius is `18px`, matching existing `.status-card`.
- Buttons and tabs use `14px` radius.
- Small badges and pills use `999px` radius.

### Deterministic Result Tone

Use coach-like but deterministic phrasing:

- Allowed:
  - `This suggests your pronunciation was mostly clear in this sample.`
  - `This metric is computed from word and phoneme scores in the JSON.`
  - `Repeated low scores suggest this sound may need practice.`
  - `These pauses are calculated from gaps between word timings.`
- Not allowed:
  - `Gemini says...`
  - `The examiner thinks...`
  - `Your IELTS examiner would score...`
  - `You definitely have a problem with...`

## Layout Contract

### Page Structure

Use a single analysis page with input panel on top and results below.

Order:

1. Page header.
2. JSON input card.
3. Validation preview card.
4. Results region.
5. Lightweight result tabs.

### Page Header

Content:

- Eyebrow badge: `JSON Mode`
- Title: `Analyze speech assessment JSON`
- Intro: `Paste or upload speech assessment JSON to compute deterministic pronunciation and fluency metrics. Gemini feedback and audio analysis come later.`

Visual contract:

- Page shell uses `max-width: 960px`.
- Page shell is centered with `margin: 0 auto`.
- Mobile page padding: `16px`.
- Tablet/desktop page padding: `24px`.
- Header bottom margin: `24px`.
- Header title uses Display typography.
- Intro uses Body typography and `--ink-soft`.

### Input Card

Card title: `Speech assessment JSON`

Required controls in order:

1. Textarea for pasted JSON.
2. Row of secondary actions:
   - `Upload .json file`
   - `Load sample JSON`
   - `Clear JSON`
3. JSON metadata row:
   - Character count.
   - File name if uploaded.
   - Last validation status.
4. Primary CTA: `Analyze JSON`.

Textarea contract:

- Uses mono font.
- `aria-label="Speech assessment JSON input"`.
- Placeholder: `Paste the full speech assessment JSON here.`
- No syntax highlighting in Phase 02.
- No line numbers in Phase 02 unless trivial to implement accessibly.
- Preserve pasted whitespace.
- Do not auto-analyze on paste.
- Do not send pasted JSON to Gemini or any third-party service.

Upload contract:

- Upload is secondary to paste.
- Visible trigger label: `Upload .json file`.
- Accept only `.json` and `application/json`.
- Maximum file size: `2 MB`.
- If file is too large, show: `This file is too large for JSON mode. Upload a .json file under 2 MB.`
- If file cannot be read, show: `We couldn't read this file. Try pasting the JSON instead.`

Sample action contract:

- Label: `Load sample JSON`.
- Loads `.artifacts/speech-response.json` into the textarea.
- Replaces existing input only after confirmation if textarea is non-empty: `Replace the current JSON with the sample JSON?`
- After loading, show validation preview automatically.

Clear action contract:

- Label: `Clear JSON`.
- If textarea or results are non-empty, require confirmation: `Clear the pasted JSON and current results? This cannot be undone.`
- Clears input, validation preview, warnings, and results.

### Validation Preview Card

Validation preview appears below the input card.

Required states:

1. Empty.
2. Checking.
3. Parseable but not backend-validated.
4. Valid.
5. Valid with warnings.
6. Invalid.

Backend validation ownership:

- The backend is the source of truth for schema validation.
- Frontend may perform JSON syntax parsing only to avoid sending unreadable text.
- Backend returns learner-friendly labels and exact JSON paths.
- Backend returns warnings for suspicious-but-computable values.

Preview behavior:

- After paste, upload, or sample load, wait `600ms` after typing stops.
- If the text is parseable JSON, request backend validation preview.
- Do not compute or render full metrics from the validation preview.
- Enable `Analyze JSON` only when the latest backend preview is `valid` or `valid_with_warnings`.
- If preview is invalid, keep `Analyze JSON` disabled.

Validation issue display:

- Show top 3-5 issues first.
- If more than 5 issues exist, show: `Showing 5 of {count} issues.`
- Provide `Show all issues`.
- Each issue row must contain:
  - Learner-friendly label.
  - Exact JSON path.
  - Short fix hint when available.
- Technical details are collapsed by default under `Show technical details`.

Issue row format:

```text
Missing word timings
path: result[12].start_time
Add start_time and end_time for each word.
```

Malformed JSON display:

- Friendly summary first: `This does not look like valid JSON yet.`
- Helper: `Check for a missing comma, quote, or closing bracket.`
- Technical parser error hidden by default.

Warning display:

- Warning callout heading: `Analyzable with warnings`
- Body: `Metrics will still be computed, but review these unusual values.`
- Warning rows use warning color, not danger color.

### Results Region

Results appear only after the user activates `Analyze JSON` and receives a successful analysis response.

Results order:

1. Summary metric cards.
2. Deterministic explanation card.
3. Tabs: `Summary`, `Words`, `Phonemes`, `Pauses`.

If analysis is running:

- Keep input card visible.
- Disable `Analyze JSON`.
- Button label becomes `Analyzing...`.
- Show status text: `Computing deterministic metrics from the JSON...`
- Use `aria-live="polite"`.

If backend analysis fails:

- Show error card: `We couldn't analyze this JSON. The backend may be unavailable or the response did not match the contract.`
- Include next step: `Check the validation preview, then try Analyze JSON again.`
- If available, show technical details collapsed.

## Interaction Contract

### Primary Flow

1. User pastes JSON into textarea.
2. UI waits `600ms` after typing stops.
3. UI performs local JSON syntax check.
4. If parseable, UI sends JSON to backend validation preview.
5. UI shows validation preview.
6. If valid or valid with warnings, `Analyze JSON` becomes enabled.
7. User selects `Analyze JSON`.
8. UI sends JSON to backend analysis route.
9. UI renders deterministic results.
10. User inspects details through `Summary`, `Words`, `Phonemes`, and `Pauses` tabs.

### Sample JSON Flow

1. User selects `Load sample JSON`.
2. If existing input is non-empty, confirm replacement.
3. UI loads canonical sample JSON content.
4. UI triggers validation preview.
5. User selects `Analyze JSON`.
6. UI renders sample deterministic metrics.

### Upload Flow

1. User selects `Upload .json file`.
2. UI validates file type and size.
3. UI reads file text into textarea.
4. UI triggers validation preview.
5. User selects `Analyze JSON`.

### Tab Behavior

Tabs:

- `Summary`
- `Words`
- `Phonemes`
- `Pauses`

Rules:

- Default active tab after successful analysis: `Summary`.
- Tabs are implemented as buttons with `role="tab"` if using ARIA tab pattern.
- Active tab must be keyboard-focusable and visibly selected.
- Left/right arrow navigation is recommended if implementing full ARIA tabs.
- If simple buttons are used instead of ARIA tabs, use `aria-pressed` and keep markup simple.

### Disabled Button Rules

`Analyze JSON` is disabled when:

- Textarea is empty.
- JSON syntax is invalid.
- Backend validation preview is invalid.
- Validation preview is still checking.
- Analysis request is in flight.

Disabled button helper copy:

- Empty: `Paste JSON or load the sample to continue.`
- Invalid: `Fix validation issues before analyzing.`
- Checking: `Wait for validation preview to finish.`

## Result Content Contract

### Summary Metric Cards

Show these five metrics in this exact order:

1. Pronunciation percentage.
2. Pronunciation Band.
3. Fluency Band.
4. WPM.
5. Pause ratio.

Each metric card contains:

- Label.
- Main value.
- Short deterministic helper.

Required helper copy:

| Metric | Helper |
|--------|--------|
| Pronunciation percentage | `Computed from word and phone scores.` |
| Pronunciation Band | `Estimated from deterministic score thresholds.` |
| Fluency Band | `Estimated from WPM, pause ratio, and critical pauses.` |
| WPM | `Words per minute from word timings.` |
| Pause ratio | `Share of speaking time spent in detected pauses.` |

Value formatting:

- Pronunciation percentage: integer percent, e.g. `86%`.
- IELTS-style bands: one decimal, e.g. `6.5`.
- WPM: integer, e.g. `112`.
- Pause ratio: integer percent, e.g. `18%`.

### Summary Tab

Required sections:

1. `What this means`
2. `Pronunciation signals`
3. `Fluency signals`
4. `Warnings` if warnings exist

Copy tone:

- Deterministic.
- Coach-like.
- No Gemini/examiner claims.

Example summary copy pattern:

```text
This suggests the sample was mostly understandable, with a few lower-scoring sound patterns to review.
```

### Words Tab

Purpose: show color-banded weak/okay/good word list with score and timing.

Required row fields:

- Word.
- Band: `Weak`, `Okay`, or `Good`.
- Score as percent.
- Timing range in seconds.

Row format:

```text
canoe
Good - 97%
1.05s-1.53s
```

Sorting:

- Default: original speech order.
- Provide no sorting controls in Phase 02.
- Use visual color banding without relying on color alone by including `Weak`, `Okay`, or `Good`.

Band thresholds:

- Weak: `< 0.65`
- Okay: `>= 0.65` and `< 0.85`
- Good: `>= 0.85`

Empty state:

- Heading: `No major weak words found.`
- Body: `Most word scores are in the okay or good range for this sample.`

### Phonemes Tab

Purpose: show top 5 repeated weak ARPAbet phones by low score, with IPA examples.

Required fields:

- ARPAbet phone.
- IPA examples.
- Average score.
- Weak occurrence count.
- Example words if returned by backend.

Rules:

- Show maximum 5 repeated weak phones.
- A repeated weak pattern requires at least 2 low-scoring occurrences.
- Use ARPAbet label as primary identifier and IPA as secondary.
- Do not show a full phoneme analytics dashboard in Phase 02.

Row format:

```text
IH2 /ih/
3 weak occurrences - average 61%
Examples: slid, ...
```

Empty state:

- Heading: `No repeated weak pattern found.`
- Body: `The JSON did not show the same low-scoring phone repeated at least twice.`

### Pauses Tab

Purpose: show notable pauses with severity, duration, and nearby words.

Required fields:

- Severity label.
- Duration.
- Timing gap.
- Nearby words.

Severity labels:

- `Natural`
- `Noticeable`
- `Long`
- `Critical`

Rules:

- Sort pauses by duration descending.
- Include exact duration in seconds.
- Include nearby words/context where backend provides it.
- Do not build SVG timeline in Phase 02; timeline is deferred to Phase 06.

Row format:

```text
Long pause
1.8s between "about" and "Da"
This suggests a planning or word-search pause.
```

Empty state:

- Heading: `No notable pauses found.`
- Body: `The word timings did not include pauses long enough to flag in this analysis.`

## State Contract

### Empty State

Shown before any input.

Visual:

- Beige soft panel inside input card.
- No red/error styling.

Copy:

- Heading: `Paste speech assessment JSON to begin.`
- Body: `Use your speech assessment response, upload a .json file, or load the sample JSON to preview deterministic pronunciation and fluency metrics.`

### Loading States

Validation loading:

- Text: `Validating speech assessment fields...`
- Keep textarea editable.
- Do not clear previous valid results until a new analysis succeeds or user clears input.

Analysis loading:

- Text: `Computing deterministic metrics from the JSON...`
- Disable `Analyze JSON`.
- Keep result tabs from previous successful analysis visible but visually mark as stale only if input changed: `Input changed. Analyze again to update results.`

### Success State

Show:

- Validation preview: `This JSON can be analyzed.`
- Results region with metric cards and tabs.
- If warnings exist, show warning callout above metrics.

### Warning State

Show warning callout when backend returns suspicious-but-computable values.

Copy:

```text
Analyzable with warnings
Metrics will still be computed, but review these unusual values.
```

### Error State

Validation errors and backend errors must not use raw stack traces as the primary message.

Primary message:

```text
We couldn't read this JSON yet. Fix the highlighted issue, then try Analyze JSON again.
```

Technical details:

- Collapsed by default.
- Can include parser message, HTTP status, Zod path, or backend diagnostic.
- Must not expose secrets or environment values.

## Accessibility Contract

### Keyboard

- All interactive controls must be reachable by keyboard.
- Focus order:
  1. Textarea.
  2. Upload .json file.
  3. Load sample JSON.
  4. Clear JSON.
  5. Analyze JSON.
  6. Validation details controls.
  7. Result tabs.
  8. Result content controls.
- Minimum hit target: `44px`.
- Focus visible state:
  - `outline: 2px solid var(--accent)`
  - `outline-offset: 2px`

### Screen Readers

- Main content uses `<main>`.
- Page header uses one `<h1>`.
- Each card has a semantic heading.
- Async validation and analysis status uses `aria-live="polite"`.
- Error summaries use `role="alert"` only when blocking progress.
- Warning callouts use `role="status"` or normal semantic region; do not overuse alerts.
- Textarea has explicit accessible label.
- File input trigger has explicit label and accepted file hint.
- Tabs must expose selected state using either ARIA tab pattern or button group with `aria-pressed`.

### Color and Contrast

- Do not rely on color alone for status.
- Every score band must include a text label.
- Error rows must include `Invalid`, `Missing`, or equivalent text, not just red styling.
- Warning rows must include `Warning`.
- Ensure text contrast meets WCAG AA for body text, muted metadata, and white text on primary ink button.

### Motion

- No required animations.
- If subtle transitions are used, keep duration `<= 150ms`.
- Respect `prefers-reduced-motion`.

## API/UI Boundary Contract

Frontend responsibilities:

- Capture pasted/uploaded/sample JSON.
- Perform local JSON syntax parsing only for basic readability.
- Request backend validation preview.
- Request backend deterministic analysis after manual `Analyze JSON`.
- Render backend validation issues, warnings, and metrics.
- Validate backend responses with shared Zod contracts before rendering success UI.

Backend responsibilities:

- Own schema validation.
- Own deterministic metric computation.
- Return learner-friendly validation labels and exact JSON paths.
- Return warning callouts for suspicious-but-computable values.
- Return deterministic pronunciation and fluency outputs.

Frontend must not:

- Compute authoritative metrics.
- Call Gemini.
- Send JSON to third-party services.
- Persist analysis history.
- Pretend deterministic metrics are examiner or Gemini feedback.
