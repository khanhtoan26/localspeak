<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| vendor JSON -> shared schemas | Untrusted vendor-shaped objects enter runtime validation and deterministic metric computation. |
| metric helpers -> API/UI consumers | Bad numeric outputs could mislead learners or crash rendering if not finite. |
| validation technical detail -> learner UI | Technical strings are displayed behind details controls and must stay safe. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-02-01 | Tampering/DoS | `computeJsonAnalysis`, metric helpers | mitigate | Validate non-empty `result` and phones, score ranges, timing ranges, finite duration/WPM/ratios; tests cover empty, overlapping, zero-duration, low/high WPM variants. |
| T-02-02 | Information Disclosure | `toValidationIssues` technical fields | mitigate | Map Zod issues to safe labels/paths/hints; never include stack traces, env names, or raw exception objects. |
| T-02-03 | Information Disclosure | `JsonAnalysisResponseSchema` | mitigate | Strict response schema omits full `speechAssessment` per D-20 and returns only derived/extracted fields, warnings, and metrics. |
| T-02-04 | Repudiation/Tampering | Locked metric constants | mitigate | Export named constants and pin D-17/D-18/D-19 tests to exact values so backend/UI cannot drift. |
| T-02-05 | Information Disclosure | Third-party/Gemini sharing | mitigate | No network or Gemini/Supabase code in contracts; tests/static acceptance confirm pure functions only. |
</threat_model>
