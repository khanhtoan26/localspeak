<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser/client -> NestJS API | Untrusted JSON request bodies cross into backend preview/analyze endpoints. |
| API -> shared contract helpers | API delegates validation/metrics to shared deterministic code and must revalidate on analyze. |
| API errors -> learner UI | API error payloads can become technical details in the browser. |
| Local fixture -> API response | Canonical sample JSON is read server-side and returned intentionally through sample endpoint. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-02-06 | Denial of Service | `main.ts`, controller body guard | mitigate | Configure 2 MB JSON body limit and parsed-size guard; e2e oversized body test expects safe non-2xx response. |
| T-02-07 | Information Disclosure | preview/analyze error responses | mitigate | Return only validation codes, paths, labels, hints, safe technical strings; e2e asserts no secrets or stack traces. |
| T-02-08 | Information Disclosure | third-party/Gemini boundary | mitigate | No Gemini/Supabase/analytics calls in JsonAnalysisModule; e2e/static assertions cover absence. |
| T-02-09 | Tampering | stale preview vs analyze drift | mitigate | Analyze endpoint parses and validates independently; preview success is never trusted as authorization to compute. |
| T-02-10 | Information Disclosure | analyze success payload | mitigate | Parse through strict `JsonAnalysisResponseSchema` and omit full original `speechAssessment` per D-20. |
| T-02-11 | Elevation/Tampering | backend contract bypass | mitigate | Controller parses request and response with shared Zod schemas before returning; invalid analyze contracts fail safely. |
</threat_model>
