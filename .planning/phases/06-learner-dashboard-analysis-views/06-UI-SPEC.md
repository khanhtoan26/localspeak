## Spacing Scale

Declared values must remain multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, pill dot gaps, compact chip internals |
| sm | 8px | Button/tab padding increments, chip gaps, metric value spacing |
| md | 16px | Default card padding, form spacing, result row padding |
| lg | 24px | Section gaps, page padding, audio/live panel spacing |
| xl | 32px | Header top spacing, dashboard hero rhythm |
| 2xl | 48px | Major dashboard section breaks on wide layouts |
| 3xl | 64px | Reserved for page-level separation only; avoid inside cards |

Exceptions:

- Interactive controls must have a minimum target height of **44px**.
- Rounded pills may use `border-radius: 999px`.
- Existing card radius is **18px** and should remain the Phase 6 card radius.
- Existing button/input/tab radius is **14px** and should remain the Phase 6 control radius.
- SVG pause timeline geometry may use computed pixel widths, but vertical spacing, labels, legend gaps, and row padding must use the declared scale.

## Typography

Use exactly these four sizes and two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / Meta | 11px | 600 | 1.2 |
| Body / Button / Tab | 16px | 400 or 600 | 1.5 |
| Section Heading | 20px | 600 | 1.2 |
| Display / Metric Value | 32px | 400 | 1.1 |

Additional typography rules:

- Use `Instrument Serif` only for page-level display headings such as `LocalSpeak` and the main dashboard title.
- Use body font for dashboard priority text, tab labels, card titles, buttons, pause rows, word chips, and saved-session UI.
- Use mono font only for technical metadata: JSON validation status, timestamps, score labels, timing ranges, and compact metric details.
- Do not introduce weight `700`; existing bold metric/audio inline styles should be normalized to `600`.
- Uppercase labels must use `letter-spacing: 0.06em` to `0.08em`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fafaf7` / `var(--bg)` | Page background and dominant quiet surface |
| Secondary (30%) | `#ffffff` / `var(--card)`, plus `#f1ede4` / `var(--beige-soft)` | Cards, secondary panels, empty states, tab backgrounds, history panel |
| Accent (10%) | `#d97757` / `var(--accent)` | Active tab border, focus rings, mode tag text, AI Coach CTA emphasis, selected saved-session indicator |
| Destructive | `#9f2d20` / `var(--danger)` | Destructive or failure states only |

Accent reserved for:

- Active top-level mode tab border
- Active JSON analysis tab border
- Keyboard focus outlines
- Compact mode/status tags
- AI Coach CTA emphasis
- Current reopened saved-session marker
- Links or tertiary text actions that need learner attention

Accent must not be used for:

- All buttons by default
- Score severity states
- Destructive actions
- Decorative chart colors unrelated to user action

Semantic colors:

| Semantic Role | Text / Border | Background | Usage |
|---------------|---------------|------------|-------|
| Good / Natural | `#3f6b4f` / `var(--success)` | `#edf5ef` | Good word chips, natural pauses, successful save |
| Warning / Noticeable | `#b88a3e` / `var(--warning)` | `#f8f1df` | Okay word chips, noticeable pauses, stale result warning |
| Weak / Critical / Error | `#9f2d20` / `var(--danger)` | `#f6ebe8` | Weak word chips, critical pauses, analysis errors |
| Line | `#ebe7df` / `var(--line)` | n/a | Card borders, row borders, chart axes |

Accessibility contract:

- Pause severity must use both color and text label.
- Word chips must expose visible score text or accessible labels; color alone is not sufficient.
- SVG timeline pause segments must include accessible labels such as `Critical pause, 1.20 seconds, between "word" and "word"`.

## Phase 6 Visual Contract

### Page Shell

- Keep the current warm neutral visual identity:
  - background `var(--bg)`
  - centered shell
  - cards on `var(--card)`
  - soft beige secondary surfaces
- Increase the analysis shell width from the current narrow status shell when needed:
  - default content width: `min(100%, 1120px)`
  - dashboard + side history layout may use `min(100%, 1200px)`
- Mobile padding: `16px`.
- Desktop padding: `24px`.

### Dashboard Header

The dashboard header must answer:

> What should I practice next?

Structure:

1. Compact tag: `IELTS Coach`
2. Display title: `LocalSpeak`
3. Learner-first dashboard card titled `What should I practice next?`
4. One short priority statement.
5. One compact reason sentence.
6. Metric strip underneath.

Priority statement rules:

- Must be derived from existing analysis outputs.
- Must not invent unsupported diagnoses.
- Prefer deterministic data in this order:
  1. repeated weak phoneme pattern with high learner relevance
  2. critical or longest pause
  3. weak word concentration
  4. WPM or pause ratio issue
- Fallback copy: `Analyze a speaking attempt to see your highest-priority pronunciation or fluency issue.`

Metric strip must include:

- Pronunciation percentage
- Pronunciation Band
- Fluency Band
- WPM

Pause ratio may remain visible as a secondary metric but must not replace the four required metrics.

### Metric Cards

- Use existing `json-metric-card` style.
- Required metric card labels:
  - `Pronunciation`
  - `Pronunciation Band`
  - `Fluency Band`
  - `WPM`
- Values use 32px display size.
- Helpers use 16px body size.
- Metric cards should become 4 cards in the primary dashboard strip.
- Pause ratio can move into Pause Analysis summary.

### Top-Level Mode Switch

Keep top-level mode switching, but present modes as learner practice paths:

| Mode | Label | Description |
|------|-------|-------------|
| JSON | `JSON Analysis` | `Import assessment data to inspect scores, pauses, words, and phonemes.` |
| Audio | `Live Audio Practice` | `Record from your microphone and watch the AI coach respond live.` |

Interaction rules:

- Use `button` elements with `aria-pressed`.
- Minimum target height: 44px.
- Active mode uses accent border and ink text.
- Inactive mode uses secondary/card background and soft ink text.
- Switching modes must not clear completed JSON results unless the user explicitly clears them.

## JSON Analysis Tabs

JSON mode tabs must be:

1. `Pause Analysis`
2. `Words`
3. `Phonemes`
4. `IELTS Analysis`

The existing `Summary` tab should be absorbed into the dashboard header/priority card rather than remain a fifth required tab.

Tab interaction:

- Use `aria-pressed` or upgrade to proper tab semantics with `role="tablist"`, `role="tab"`, and `role="tabpanel"`.
- Active tab uses accent border.
- Tab list scrolls horizontally on mobile.
- Tab panels preserve deterministic results when AI states fail.

## Pause Analysis Contract

The Pause Analysis tab must be timeline-first.

Required order:

1. Pause summary card
2. SVG pause timeline
3. Severity legend
4. Worst pause practice cue
5. Sorted pause list

### Pause Summary

Show:

- Total pause time
- Pause ratio
- Critical pause count
- Longest pause duration

### SVG Timeline

- Render word blocks in speech order.
- Render pauses as shaded segments between word blocks.
- Severity mapping:
  - natural: success green
  - noticeable: warning amber
  - critical: danger red
- Timeline must include an accessible title and description.
- Each pause segment must expose:
  - severity
  - duration
  - before word
  - after word

### Pause List

- Sort by duration descending.
- Each row must show:
  - severity label
  - duration in seconds
  - before word
  - after word
  - timing range
  - explanation
- Required row copy pattern:
  - `{Severity} pause`
  - `{duration}s between "{beforeWord}" and "{afterWord}"`
  - `gap: {startTime}s–{endTime}s`

### Worst Pause Practice Cue

- Show one cue for the longest or most severe pause.
- Required heading: `Practice this pause first`
- Copy must reference the exact before/after words.
- Example pattern:
  - `Try saying "{beforeWord} {afterWord}" as one short phrase, then repeat the full sentence without stopping between them.`

---

## Words Tab Contract

The Words tab must show sentence-order score chips.

Required structure:

1. Sentence-order chip group
2. Legend
3. Optional weak-words shortlist

### Word Chips

- Preserve original word order.
- Each chip shows:
  - word text
  - score percent
- Chip accessible label:
  - `{word}, {band}, {scorePercent} percent, from {startTime}s to {endTime}s`
- Bands:
  - Good: score >= 90%, green
  - Okay: 70–89%, amber
  - Weak: below 70%, red
- Do not replace sentence-order chips with a sorted list.

### Weak-Words Shortlist

Show only if at least one weak word exists.

- Heading: `Weak words to repeat`
- Sort by lowest score first.
- Limit to 5 words.
- Keep this section secondary to the sentence-order chip view.

## Phonemes Tab Contract

The Phonemes tab must rank weak sound patterns by learner impact.

### Ranking

Rank by a deterministic impact score that combines:

1. Lower average score
2. Higher weak occurrence count
3. IELTS/Vietnamese relevance when supported by the detected ARPAbet/IPA data

Do not show unsupported Vietnamese-specific advice.

### Row Structure

Each phoneme row must include:

- ARPAbet label
- IPA examples
- Weak occurrence count
- Average score percent
- Example words
- Horizontal weakness bar
- Brief learner explanation

Required row copy pattern:

- Title: `{ARPAbet} / {IPA examples}`
- Meta: `{weakOccurrenceCount} weak occurrences · average {scorePercent}%`
- Examples: `Examples: {words}`
- Explanation: one concise sentence explaining why this pattern matters.

### Vietnamese Learner Hints

Show hints only when analysis data matches known patterns:

| Pattern | Hint |
|---------|------|
| `/θ/` confused or weak | `Vietnamese speakers often replace /θ/ with /t/ or /d/. Keep the tongue lightly between the teeth and release air.` |
| final consonant weakness | `Final consonants affect IELTS clarity. Finish the last sound instead of dropping it.` |
| clusters such as `thr-`, `str-`, `tr-` | `Consonant clusters need each sound to stay audible. Slow the cluster first, then return to normal speed.` |

If no supported pattern is detected, omit Vietnamese hint copy.

## IELTS Analysis / AI Coach Contract

AI coaching remains opt-in and must not hide deterministic metrics.

### Trigger

- Button label: `Get AI Feedback`
- Disabled/loading label: `Generating…`
- Place after dashboard metrics and before/inside the `IELTS Analysis` tab as long as it is visually tied to AI Coach.
- Deterministic dashboard, pause, words, and phoneme tabs must remain visible during loading/error.

### States

| State | Visual Contract |
|-------|-----------------|
| Idle | Secondary card explaining that AI feedback is optional after deterministic review |
| Loading | Card with skeleton/progress feel and `Generating personalized IELTS feedback…` |
| Success | Show bands, top errors, drills, and summary using existing contract |
| Error | Danger card with retry button; deterministic results remain visible |
| Retry | Same as initial trigger; no full-page reset |

### Streaming Feel

For JSON-mode AI feedback:

- Do not require a true backend streaming change in Phase 6.
- Use polished loading/progress states compatible with the existing strict JSON feedback endpoint.

For audio mode:

- Preserve the live incremental analysis panel from Phase 4 decisions.
- The live panel should use a dark or muted secondary background to distinguish streaming output from inputs.

## Audio Mode Contract

Audio mode remains a top-level practice path.

Required order:

1. Reference sentence input
2. Record/stop button with waveform or level meter
3. Live analysis panel
4. Post-recording score summary, if available

Interaction rules:

- Reference text is required before recording.
- Record button disabled until reference text is non-empty.
- First Record press may trigger microphone permission.
- While recording:
  - button label becomes `Stop Recording`
  - show pulsing red indicator
  - waveform/level meter animates
  - live analysis text updates incrementally
- On stop:
  - final text remains visible until a new recording starts

Error copy:

| Error | Copy |
|-------|------|
| Microphone denied | `Microphone access is required. Please allow microphone access in your browser settings.` |
| Connection failed | `Unable to connect to AI coach. Check your internet connection and try again.` |
| Connection lost | `Connection lost — please try again.` |

Implementation note:

- Current code references `useDeepgramSession`; Phase 6 planning must verify whether Phase 4 Gemini Live implementation has replaced this. UI labels must say Gemini/AI coach only if the implementation actually uses Gemini Live.

## Saved-Session UI Contract

Phase 6 includes lightweight saved-session UX.

Scope:

- Explicit save
- History list
- Reopen saved session

Out of scope:

- Rename
- Delete
- Account linking
- Authentication
- Advanced progress analytics

### Placement

Saved-session controls must be secondary.

Acceptable layouts:

1. Right-side panel on desktop, below dashboard on mobile
2. Collapsible card under the dashboard header
3. Lightweight dialog opened from `History`

Do not create a top-level `History` mode unless layout becomes too cramped.

### Save Control

- CTA: `Save Result`
- Place near current result actions, secondary to `Analyze JSON` and `Get AI Feedback`.
- Success copy: `Saved to this browser's history.`
- Error copy: `We couldn't save this result. Check your connection and try again.`

### History List

Each saved session row must show:

- title or reference text fallback
- input mode
- created date/time
- Pronunciation Band
- Fluency Band
- WPM
- `Reopen Result` action

History empty state:

- Heading: `No saved attempts yet`
- Body: `Save a result to reopen it later from this browser.`

### Reopen Behavior

- Reopening a saved session restores the saved metrics snapshot.
- Reopened session should display a compact marker:
  - `Reopened saved result`
- Reopening must not recompute analysis.
- If feedback exists in the saved snapshot, show it in IELTS Analysis.
- If feedback is absent, IELTS Analysis returns to idle AI Coach state.

## Accessibility Contract

- All buttons must be keyboard focusable with `2px solid var(--accent)` focus outline and `2px` offset.
- All controls must meet minimum target height of 44px.
- Mode switch and tab switch must expose selected state.
- Dynamic analysis/loading/errors must use `aria-live="polite"` unless the message is destructive or urgent.
- SVG timeline must include accessible labels for pauses and not rely on color alone.
- Word chips must include score and band in accessible text.
- Saved-session list rows must have unique, descriptive Reopen buttons, e.g. `Reopen result from May 8, 2026`.

---

## Responsive Contract

### Mobile: up to 640px

- Page padding: 16px
- Metric grid: 1 column
- Mode switch and tab list: horizontal scroll if needed
- Saved history: below current result, collapsed by default if long
- Word chips wrap naturally
- Timeline may horizontally scroll, but labels and legend remain visible

### Tablet: 641px–1023px

- Metric grid: 2 columns
- Dashboard and result tabs remain single-column
- Saved history appears below or as collapsible card

### Desktop: 1024px+

- Metric grid: 4 columns for headline metrics
- Optional two-column layout:
  - main dashboard/results: flexible primary column
  - saved history: secondary column
- Do not exceed `1200px` page shell width.
