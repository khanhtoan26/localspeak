The `apps/web` directory has **no** `components.json`, `tailwind.config.ts`, or tailwind dependencies.

any shadcn components. Use the default "New York" style with the warm color palette defined in this
spec. After init, confirm `components.json` is present before proceeding.

## Spacing Scale

Declared values (all multiples of 4 — 8-point scale):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, inline badge padding, sidebar active indicator width |
| sm | 8px | Chip padding, tab list gap, compact row gap, sidebar item gap |
| md | 16px | Default card padding, form field spacing, section gap within a card |
| lg | 24px | Between major card sections, metric grid gap, results region gap |
| xl | 32px | Page header top padding, between layout regions |
| 2xl | 48px | Major section breaks (e.g., between header and content area) |
| 3xl | 64px | Reserved — page-level maximum spacing (not used in Phase 7 panels) |

Exceptions:
- Touch targets (all interactive elements): minimum 44px height/width — hard requirement (source: CONTEXT.md D-14, UIX-07)
- Mobile page padding: 8px
- Sidebar sticky top offset: 24px desktop, 8px mobile

## Typography

Four roles, two weights. Display role uses Instrument Serif; all others use Inter.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 32px | 400 (regular) | 1.1 | Page title "LocalSpeak", large metric values (pronunciation %, band numbers) |
| Heading | 20px | 600 (semibold) | 1.2 | Card titles, section headings, tab panel headings |
| Body | 16px | 400 (regular) | 1.5 | Descriptions, helper text, metric labels, list items, input placeholder |
| Label | 11px | 600 (semibold) | 1.2 | Uppercase mono labels (IELTS COACH tag, metric card labels, sidebar eyebrow, badge text) — uses JetBrains Mono, letter-spacing 0.06em, text-transform uppercase |

**Weight palette: exactly two weights — 400 (regular) and 600 (semibold). No 500 or 700.**

Tailwind config mappings:
- `text-xs` override → 11px (Label role)
- `text-sm` → not used in Phase 7 panels (skip to avoid ambiguity)
- `text-base` → 16px (Body)
- `text-xl` → 20px (Heading)
- `text-4xl` → 32px (Display)

## Layout Contract

### Desktop (>640px): Sidebar-Left Shell

```
┌─────────────────────────────────────────────────────┐
│  [sidebar 180–220px sticky]  │  [content area flex]  │
│                              │                        │
│  LocalSpeak                  │  [active panel]        │
│  ─────────                   │                        │
│  Practice Tools              │                        │
│    ▸ JSON Analysis           │                        │
│    ▸ Live Audio Practice     │                        │
│                              │                        │
└─────────────────────────────────────────────────────┘
```

- Sidebar: `position: sticky; top: 24px; align-self: start`
- Sidebar width: `minmax(180px, 220px)` — same as existing pattern
- Content: `minmax(0, 1fr)` — prevents overflow
- Layout gap: 16px (`md` token)
- Max content width: 1200px (JSON mode, matches existing `status-shell--dashboard`)
- Max content width: 1040px (Audio mode, matches existing `status-shell--practice`)

### Mobile (≤640px): Bottom Navigation Bar

At phone width, the sidebar is **replaced entirely** by a fixed bottom navigation bar
(source: CONTEXT.md D-08). No hamburger menu.

```
┌────────────────────────────────┐
│  [single-column content]       │
│                                │
│                                │
├────────────────────────────────┤
│  [JSON icon]  │  [Audio icon]  │  ← fixed bottom nav
│  JSON Analysis│ Live Audio     │
└────────────────────────────────┘
```

- Bottom nav height: 64px (accounts for safe-area-inset on iOS)
- Content bottom padding at mobile: 64px + 8px clearance = 72px
- Each nav item: icon (24px) centered above label (11px Label role)
- Active item: accent color icon + label, accent underline or indicator
- Touch target per nav item: minimum 44px height (full bar covers this)
- Bottom nav background: `card` (#ffffff) with top border `#ebe7df`

### Sidebar Navigation Structure (source: CONTEXT.md D-06)

```
LocalSpeak                    ← app name, Display role, no interactive
─────────────────────         ← Separator
Practice Tools                ← section label, Label role (uppercase mono)
  ▸ JSON Analysis             ← nav item
  ▸ Live Audio Practice       ← nav item
```

- Active nav item: left accent bar (3px wide, full height, rounded, `#d97757`), background `#f1ede4`
- Inactive nav item: no background, `ink-soft` text on hover
- Sidebar shows **only shipped sections** — no coming-soon items (source: CONTEXT.md D-07)
- Section label ("Practice Tools") uses Label role typography
- Future "Exam Practice" group added in Phase 8 — NOT in Phase 7

## Component States Contract

### JSON Analysis Panel (JsonAnalysisPanel)

Visual hierarchy — outcome first, input secondary (source: CONTEXT.md D-11, UIX-04):

1. **Priority action card** (top): practice priority headline + one-sentence reason (Heading + Body)
2. **Metric cards row** (Shadcn Card × 4): Pronunciation %, Pronunciation Band, Fluency Band, WPM
3. **Result tabs** (Shadcn Tabs): Pause Analysis | Words | Phonemes | IELTS Analysis
4. **JSON input collapsible** (Shadcn Collapsible): collapsed by default after analysis completes; expanded on initial load or when user needs to re-paste

JSON input states:
- **Pre-analysis**: Collapsible open, Textarea visible, "Analyze Pronunciation" primary button enabled when text present
- **Analyzing**: Button disabled (`opacity: 0.56`), Skeleton replaces metric cards
- **Post-analysis**: Collapsible auto-collapsed; metrics and tabs visible; "Edit Input" or disclosure summary to re-open
- **Stale**: Warning banner (warning color, Body role) above metrics when input has changed since last analysis

### Audio Mode Panel (AudioModePanel)

Simple speaking flow (source: CONTEXT.md D-11, UIX-05):

1. **Reference text input** (Shadcn Input): full-width, placeholder "Enter the sentence you want to practice..."
2. **Record controls**: RecordButton centered in its section, waveform below when recording
3. **Status indicator**: idle / connecting / recording / complete — Badge component, semantic colors
4. **Live transcript** (LiveAnalysisPanel): appears during/after recording
5. **Score card** (Shadcn Card): WordScoreCard appears post-recording — overall score, word chips, fluency meta

Audio session states:
- **idle**: Record button enabled only when reference text is non-empty; disabled state explicit (`cursor: not-allowed, opacity: 0.56`)
- **connecting**: Button shows spinner, label "Connecting…"
- **recording**: Button shows stop icon, waveform animates, live transcript updates
- **complete**: Score card appears, button resets to idle state
- **error**: Error message in danger color below record button; "Try again" link button

### Metric Cards (SummaryMetricCards)

Shadcn Card, 4-column grid desktop, 2-column grid mobile:
- Label: 11px semibold mono uppercase (`ink-muted`)
- Value: 32px regular (`ink`) — Display role
- Helper: 16px regular (`ink-soft`) — Body role

### Tab Content States

All four tabs must handle:
- **Empty/no data**: Empty state message (see Copywriting section)
- **Loaded**: Content as designed
- **Loading (IELTS Analysis only)**: Skeleton rows while AI feedback generates

### Loading States

Use Shadcn Skeleton for:
- Metric cards while analysis is running (4 × skeleton card)
- AI Coach content while generating (3 × skeleton line)

Skeleton background: `#f1ede4` (beige-soft) — warmer than default gray skeleton

### Focus States

All interactive elements: `outline: 2px solid #d97757; outline-offset: 2px` (accent color).
This applies to: buttons, inputs, textarea, tabs, sidebar nav items, summary disclosure, bottom nav items.
Must be `focus-visible` only (not `focus`) to avoid mouse-click outlines.

## Responsive Behavior Contract

### Breakpoints

| Breakpoint | Width | Layout change |
|------------|-------|---------------|
| Mobile | ≤640px | Sidebar → bottom nav; single-column content; metric grid 2-col |
| Desktop | >640px | Sidebar-left layout; metric grid 4-col |

No intermediate tablet breakpoint required for Phase 7.

### No Horizontal Overflow (Hard Requirement — UIX-06)

- All containers: `min-width: 0` on flex/grid children
- Textarea: `width: 100%; max-width: 100%`
- Metric grid: CSS Grid with `minmax(0, 1fr)` columns
- Word chip list: `flex-wrap: wrap`
- Content area: `minmax(0, 1fr)` in grid, never `overflow: visible` on a constrained column
- Bottom nav at mobile: `position: fixed; bottom: 0; left: 0; right: 0; width: 100%`

### Touch Targets (UIX-07)

Every interactive element minimum: 44×44px. Applies to:
- All Button variants
- Sidebar nav items (padding to reach 44px height)
- Bottom nav items (full bar height = 64px satisfies this)
- Tab triggers
- Collapsible summary/trigger
- Record button

## Accessibility Contract (UIX-07)

| Area | Requirement |
|------|-------------|
| Semantic landmarks | `<header>`, `<nav>` (sidebar + bottom nav), `<main>`, `<aside>` used correctly |
| Nav labeling | Sidebar `<nav aria-label="Main navigation">`, bottom nav `<nav aria-label="Main navigation">` |
| Tab component | `role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`, `aria-controls` — Shadcn Tabs provides this |
| Keyboard nav | Tab key navigates all interactive elements; Enter/Space activates buttons/tabs; arrow keys within tab list |
| Active states | Sidebar active item: `aria-current="page"`. Audio status: `aria-live="polite"` on status badge |
| Loading states | `aria-busy="true"` on loading containers; Skeleton has `role="status" aria-label="Loading…"` |
| Error states | Error messages associated with their input via `aria-describedby` |
| Contrast | All text/background pairs meet WCAG AA (4.5:1 minimum for body, 3:1 for large text) |
| Screen-reader labels | Icon-only buttons use `aria-label`; tooltip provides visible label on hover/focus |
| Record button | State changes announced via `aria-label` update ("Start recording" / "Stop recording") |
