<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| shadcn registry -> source tree | Generated primitive source enters the repo. Use official shadcn registry only; no third-party registry. |
| global CSS -> all UI | Token changes affect contrast, focus visibility, and readable state indication. |
| product components -> feature surfaces | Product components must not introduce API/provider/auth behavior or unsafe rendering. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-07.1-01-01 | Tampering | `apps/web/components/ui/*` generated files | mitigate | Generate only official shadcn primitives listed in UI-SPEC; do not add LocalSpeak product logic or API calls to primitives. |
| T-07.1-01-02 | Information Disclosure | design-system components | mitigate | Do not add frontend provider keys, auth/session logic, owner keys, or API payload logging in product components. |
| T-07.1-01-03 | Denial of Service | responsive layout tokens | mitigate | Use `min-w-0`, neutral global resets, and avoid fixed-width product CSS that can cause 390px horizontal overflow. |
| T-07.1-01-04 | Elevation of Privilege | frontend/provider boundary | accept | This plan introduces no backend, auth, persistence, or provider calls; existing API boundaries remain untouched. |
</threat_model>
