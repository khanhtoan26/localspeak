<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| microphone permission/browser audio -> client hook | User microphone state and transcript enter the UI through existing audio hook. |
| transcript words -> scoring function | Browser transcript words are scored against user-provided reference text. |
| transcript/result text -> React UI | Dynamic transcript and scoring data are rendered to the page. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-07.1-04-01 | Spoofing | recording status UI | mitigate | Show explicit Badge/text for Ready, Connecting, Recording, Complete, and disabled/no-reference states. |
| T-07.1-04-02 | Tampering | scoring flow | mitigate | Preserve existing `scorePronunciation(transcript.words, referenceText)` flow and do not alter scoring algorithms. |
| T-07.1-04-03 | Information Disclosure | frontend provider/API boundary | mitigate | Do not add frontend provider keys or new provider calls; keep existing `useDeepgramSession` behavior only. |
| T-07.1-04-04 | Tampering | transcript/result rendering | mitigate | Do not use `dangerouslySetInnerHTML`; render transcript and word chips as React text/nodes. |
| T-07.1-04-05 | Denial of Service | mobile audio layout | mitigate | Default to single-column, use `min-w-0`, wrapping word chips, 44px recording button, and no duplicate controls. |
</threat_model>
