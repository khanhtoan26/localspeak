<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| user click/keyboard -> client shell state | User-controlled navigation changes visible surface. |
| disabled future nav -> current app scope | Disabled IELTS/TOEIC entries must not expose unimplemented feature flows. |
| shell -> JSON/audio feature components | Shell must preserve existing component boundaries and not alter API/provider behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-07.1-02-01 | Spoofing | disabled IELTS/TOEIC nav entries | mitigate | Mark entries disabled and `Coming soon`; disabled items must not navigate or render real feature surfaces. |
| T-07.1-02-02 | Tampering | shell state switching | mitigate | Keep `SurfaceId` union typed and only allow enabled nav items to call `onSurfaceChange`. |
| T-07.1-02-03 | Information Disclosure | frontend provider boundary | mitigate | Do not add provider keys, LLM calls, auth, persistence, or backend endpoints in app-shell files. |
| T-07.1-02-04 | Denial of Service | duplicate responsive content trees | mitigate | Render one mounted JSON section and one mounted Audio section only; hide inactive surfaces with `hidden`/`aria-hidden`. |
| T-07.1-02-05 | Elevation of Privilege | saved-session owner behavior | accept | This plan does not touch saved-session API or owner-key behavior. |
</threat_model>
