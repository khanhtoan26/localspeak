# Phase 07.1: Ground-Up Shadcn UI Rebuild - Context

**Gathered:** 2026-05-11T11:31:55.591+07:00
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 07.1 replaces the rejected Phase 7 UI frame with a ground-up shadcn/ui workbench: official shadcn Sidebar shell, route-ready navigation, product design tokens, and rebuilt JSON Analysis and Live Audio Practice surfaces. The phase preserves existing JSON/audio behavior and tests while changing visual architecture, component structure, and UI composition as needed.

This phase does NOT add question-bank browsing, timed IELTS practice sessions, rubric evaluation, TOEIC task practice, raw audio storage, authentication, or final session reports. Those remain later phases. Phase 07.1 may show disabled future IELTS/TOEIC sidebar entries, but it must not implement those capabilities.

</domain>

<decisions>
## Implementation Decisions

### New app shell and navigation

- **D-01:** Use the official shadcn Sidebar pattern for the app shell: `SidebarProvider`, `Sidebar`, `SidebarInset`, `SidebarTrigger`, grouped nav, and mobile Sidebar/Sheet behavior.
- **D-02:** Include disabled future IELTS/TOEIC practice entries in the sidebar now, clearly marked as coming soon, so the shell is route-ready for Phase 8/9.
- **D-03:** Replace the old fixed mobile bottom navigation with the shadcn mobile drawer pattern opened from the header. Do not keep the rejected custom bottom-nav frame.
- **D-04:** Build a focused workbench app frame rather than a landing-style hero dashboard. `app/page.tsx` should become a thin entry into a sidebar/header/content workspace.
- **D-05:** Use a lean product sidebar: LocalSpeak identity, concise subtitle, grouped navigation, and a small footer/status area only. Avoid coach-heavy sidebar widgets.

### Visual direction of the rebuild

- **D-06:** Target a clean professional SaaS workbench visual style: shadcn blocks-style, crisp hierarchy, neutral surfaces, excellent spacing, and minimal decoration.
- **D-07:** Remove the warm serif/premium-coach typography and radial-gradient treatment from the core app. Do not visually inherit the rejected Phase 7 premium-coach frame.
- **D-08:** Use balanced density: enough content for a serious tool, but every card must have a clear job and generous spacing.
- **D-09:** Use a light neutral shadcn design system by default. Reserve subtle IELTS/practice accent color for actions, status, and feedback states. Do not add dual-theme scope in this phase.

### JSON Analysis information architecture

- **D-10:** Before results exist, make JSON Analysis a clear input-to-validation flow: JSON input card, sample/upload actions, validation preview, and Analyze button.
- **D-11:** After analysis succeeds, order the screen as: priority action, metric summary, evidence tabs, saved history, then collapsed JSON input.
- **D-12:** Present detailed evidence through shadcn/Radix Tabs with compact evidence cards. Preserve keyboard/role behavior and keep Pause, Words, Phonemes, and IELTS/AI sections scannable.
- **D-13:** Place saved sessions as a secondary history section below the evidence/result area. Save/reopen must remain discoverable but must not compete with the current analysis result.

### Live Audio Practice flow

- **D-14:** Rebuild Live Audio Practice as a focused sentence-practice flow, not a future exam-practice cockpit.
- **D-15:** Order the audio flow as: reference text, readiness guidance, recording control, live transcript, then pronunciation score.
- **D-16:** Use a large shadcn-composed recording control card with prominent Button, status Badge, Progress/waveform area, and disabled guidance when no reference text exists.
- **D-17:** Use a single-column audio flow by default for responsive stability. A modest desktop aside is acceptable only if it remains stable and avoids phone-width overflow.

### the agent's Discretion

- Exact icons, microcopy, component boundaries, and shadcn Card/Header/Footer compositions are left to the planner/implementer as long as the decisions above are followed.
- The planner may choose exact neutral token values and one restrained accent palette in `globals.css`.
- The planner may decide whether a modest desktop aside improves Live Audio Practice, but phone-width no-overflow and primary-action visibility are hard requirements.
- The planner may choose exact disabled/future nav labels for IELTS/TOEIC entries, provided they are clearly non-interactive or clearly marked as coming soon.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `JsonAnalysisPanel` already owns JSON paste/upload, sample loading, preview validation, analyze state, warning display, stale-result handling, AI feedback request/retry, and saved-session reopen behavior. Preserve its behavior while replacing layout and composition.
- `derivePracticePriority` already produces the "what should I practice next" priority from weak phonemes, pauses, weak words, or fluency metrics. Reuse this outcome-first logic.
- `SummaryMetricCards`, `ResultTabs`, `SavedSessionsPanel`, `JsonInputCard`, and `ValidationPreviewCard` can be recomposed visually around shadcn Card, Tabs, Collapsible, Alert, Label, and ScrollArea.
- `AudioModePanel`, `useDeepgramSession`, `RecordButton`, `LiveAnalysisPanel`, and `scorePronunciation` already provide the Live Audio behavior. Rebuild around these rather than changing audio data flow.
- Existing shadcn primitives include Badge, Button, Card, Collapsible, Dialog, Input, Separator, Skeleton, Tabs, Textarea, and Tooltip. Research recommends adding Sidebar, Sheet, ScrollArea, Breadcrumb, Progress, Alert, and Label.

### Established Patterns

- Frontend interactivity is client-side React state with same-origin `/api/*` calls and Zod contract parsing from `@localspeak/contracts`.
- Deterministic JSON metrics remain primary; AI feedback is opt-in and secondary.
- Saved sessions use explicit save/list/reopen actions and temporary owner-key scoping until auth is implemented.
- Tailwind v4 tokens live in `apps/web/app/globals.css`; avoid feature-level hex literals and one-off frame styles.
- Only one mounted content tree per feature surface should exist. Do not duplicate full desktop/mobile panels or duplicate IDs.

### Integration Points

- Replace `apps/web/app/page.tsx` with a thin entry to an app-shell client component.
- Add `apps/web/components/app-shell/*` for sidebar, header, workspace, nav config, and surface rendering.
- Add product-level composed components outside `components/ui/` for metrics, action banners, state panels, recording controls, and evidence cards.
- Keep generated shadcn primitives in `apps/web/components/ui/` clean and unmodified except as standard shadcn-owned source.
- Update unit and Playwright tests alongside the shell rebuild so UIX-01 through UIX-08 remain covered.

</code_context>

<specifics>
## Specific Ideas

- The new UI should feel like a clean professional SaaS workbench, not a premium landing page or coach-heavy dashboard.
- Use a light neutral default palette with restrained action/status accents.
- Sidebar should include shipped JSON/Audio entries plus disabled or coming-soon IELTS/TOEIC entries.
- Mobile navigation should use the shadcn Sidebar drawer, not a custom bottom nav.
- JSON result order should be priority action -> metrics -> evidence tabs -> saved history -> collapsed input.
- Live Audio order should be reference text -> readiness -> record control -> transcript -> score.
- Raw sketches exist but are not packaged findings. They can be used as historical context only; this CONTEXT.md is the source of truth for Phase 07.1 planning.

</specifics>

<deferred>
## Deferred Ideas

- Full IELTS/TOEIC exam-practice cockpit remains Phase 8/9+ scope.
- Dual light/dark theme is deferred unless a later phase explicitly pulls it in.
- Dedicated right-rail or drawer-based saved history is deferred; Phase 07.1 uses a secondary history section.
- Dense analytics-board layouts are deferred unless future evidence shows learners need them.

</deferred>
