<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| user JSON text/file -> browser parser | Untrusted pasted/uploaded JSON enters client state. |
| browser -> `/api/json-analysis/preview` | Parsed JSON is sent to existing backend preview endpoint. |
| browser -> `/api/json-analysis/analyze` | Accepted JSON is sent to deterministic analysis endpoint. |
| browser -> `/api/gemini-feedback` | AI feedback request remains opt-in and Zod parsed. |
| saved session -> UI | Saved analysis data is rendered back into React UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-07.1-03-01 | Tampering | JSON preview/analyze responses | mitigate | Preserve `JsonAnalysisPreviewResponseSchema.parse`, `JsonAnalysisResponseSchema.parse`, and `JsonAnalysisSampleResponseSchema.parse`. |
| T-07.1-03-02 | Information Disclosure | provider/API boundary | mitigate | Do not add frontend provider keys; continue same-origin `/api/*` calls only. |
| T-07.1-03-03 | Information Disclosure | saved-session owner behavior | mitigate | Do not change saved-session owner-key save/list/reopen behavior; only recompose UI placement. |
| T-07.1-03-04 | Tampering | analysis/transcript text rendering | mitigate | Do not use `dangerouslySetInnerHTML`; render all words, evidence, AI feedback, and warnings as React text/nodes. |
| T-07.1-03-05 | Denial of Service | long JSON/evidence content | mitigate | Use `min-w-0`, wrapping chips, shadcn `ScrollArea` where needed, and keep 390px no-overflow constraints. |
</threat_model>
