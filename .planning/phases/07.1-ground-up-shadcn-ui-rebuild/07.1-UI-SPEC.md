# Phase 07.1 - UI Design Contract

> Visual and interaction contract for the Phase 07.1 ground-up shadcn/ui rebuild. Generated from REQUIREMENTS.md, Phase 07.1 CONTEXT.md, Phase 07.1 RESEARCH.md, existing shadcn config, and current rejected UI source.

---

## Design Thesis

Phase 07.1 is a ground-up shadcn/ui SaaS workbench rebuild, not a polish pass over the rejected Phase 7 frame.

LocalSpeak should feel like a focused IELTS speaking-practice workbench: calm, neutral, structured, and action-oriented. The interface should help the learner answer one question on every major screen: "What should I do next to improve my pronunciation or fluency?"

The rebuild must preserve existing JSON Analysis and Live Audio behavior while replacing the visual architecture, app shell, navigation, layout hierarchy, and component composition.

### Hard Design Contracts

- Use the official shadcn Sidebar app shell: `SidebarProvider`, `Sidebar`, `SidebarInset`, `SidebarTrigger`, grouped navigation, and mobile Sidebar/Sheet drawer behavior.
- Replace the old fixed mobile bottom nav with the shadcn mobile drawer.
- Build a focused app workbench, not a landing-page hero dashboard.
- Use a lean sidebar identity: LocalSpeak name/logo, concise subtitle, grouped nav, and small footer/status only.
- Use a clean professional SaaS visual style: shadcn blocks-style hierarchy, neutral surfaces, crisp spacing, and minimal decoration.
- Remove warm serif/premium-coach typography and radial-gradient treatment from the core app.
- Use a balanced-density light neutral shadcn system.
- Reserve accent color only for actions, status, focus, and feedback.
- Do not add dual-theme scope in this phase.

### Anti-Goals

Do not implement or visually imply fully available future exam-practice surfaces in Phase 07.1.

Out of scope:

- Question-bank browsing.
- Timed IELTS practice sessions.
- TOEIC task practice.
- IELTS rubric evaluation.
- Final session reports.
- Auth/account linking.
- Raw audio storage.
- Dark theme.
- Dense analytics dashboard.
- Landing-page hero marketing treatment.

## Spacing Scale

Declared values must be multiples of 4.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge inner gaps, tight inline spacing |
| sm | 8px | Compact element spacing, menu item gaps, small stack gaps |
| md | 16px | Default card/content padding on phone, form control spacing |
| lg | 24px | Desktop card padding, section gaps, shell content padding |
| xl | 32px | Major page section gaps, large result groups |
| 2xl | 48px | Large desktop vertical rhythm only |
| 3xl | 64px | Rare page-level spacing; avoid inside dense workbench panels |

### Spacing Exceptions

| Exception | Value | Usage |
|-----------|-------|-------|
| Minimum touch target | 44px | Buttons, sidebar trigger, menu buttons, upload labels, tab triggers where practical |
| App header height | 56-64px | shadcn SidebarInset header; use 56px phone/tablet, 64px desktop if needed |
| Sidebar width | shadcn default | Do not hand-roll a custom rail width unless required by shadcn Sidebar API |
| Phone viewport baseline | 390px | Must pass no-horizontal-overflow and visible-primary-action checks |
| Waveform bars | 4px minimum visual height | Decorative recording waveform only; not a layout spacing token |

## Typography

Use product UI sizes based on system sans. Do not use a serif display family in the core app.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label / metadata | 12px | 600 | 1.35 |
| Body | 14px | 400 | 1.5 |
| Section heading | 20px | 600 | 1.25 |
| Page heading | 28px | 600 | 1.2 |

### Typography Rules

- Use only weights `400` and `600` unless shadcn primitive defaults require otherwise.
- Remove `Instrument Serif` / warm serif display typography from core app UI.
- Use Inter/system sans for headings and body.
- Monospace is allowed only for JSON textarea contents, code-like metadata, and compact validation/status metadata.
- Do not use oversized landing-page headings.
- Page headings must fit phone width without wrapping into awkward one-word lines.
- Body copy should be concise and instructional, not marketing-led.

## Color

Use a light neutral shadcn system. Accent is restrained and never decorative.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FAFAFA` | App background, main workspace background |
| Secondary (30%) | `#FFFFFF` / `#F5F5F5` | Cards, sidebar, header, nav groups, secondary panels |
| Accent (10%) | `#2563EB` | Primary actions, active nav indicator, selected evidence state, focused positive feedback |
| Success | `#16A34A` | Good score/status feedback only |
| Warning | `#D97706` | Validation warnings, stale-result notices, caution states |
| Destructive | `#DC2626` | Destructive actions and destructive confirmations only |

Accent may be used only for:

- Primary CTA buttons: `Analyze Pronunciation`, `Start Recording`, and active workflow controls.
- Active sidebar/nav state.
- Focus-visible ring when not using the default shadcn ring.
- Status badges for the current active workflow.
- Progress indicators and selected evidence emphasis.
- Links/actions that directly advance the learner's current task.

Accent must not be used for decorative blobs, radial gradients, large hero backgrounds, every icon, static card borders, non-action labels, or disabled future nav entries.

## Radius, Elevation, and Density

| Token | Value | Usage |
|-------|-------|-------|
| Small radius | 8px | Badges, compact controls, tab triggers |
| Medium radius | 12px | Inputs, buttons, menu buttons |
| Large radius | 16px | Cards and panels |
| Extra-large radius | 20px max | Prominent recording/action card only |
| Elevation default | `shadow-sm` or none | Cards and sidebar inset surfaces |
| Elevation strong | Avoid | No premium floating hero panels |
| Border | Neutral 1px border | Primary separation mechanism |

### Density Contract

- Use balanced SaaS density.
- Every card must have one job.
- Do not create large decorative dashboard cards without learner action or evidence.
- Prefer stacked clear sections over dense multi-column analytics panels.
- Result evidence may be compact, but tabs/cards must remain readable at 390px.

## App Shell Contract

### Required Structure

Use this composition:

```text
SidebarProvider
|-- AppSidebar
|   `-- Sidebar
|       |-- SidebarHeader
|       |-- SidebarContent
|       |   |-- SidebarGroup: Practice
|       |   `-- SidebarGroup: Coming soon
|       |-- SidebarFooter
|       `-- SidebarRail
`-- SidebarInset
    |-- AppHeader
    |   |-- SidebarTrigger
    |   |-- Separator
    |   `-- Breadcrumb / current surface title
    `-- main workspace
```

### Shell Rules

- `app/page.tsx` must become a thin entry into the new workspace shell.
- Desktop must use shadcn Sidebar, not a custom sticky rail.
- Mobile must use the shadcn Sidebar drawer/Sheet behavior opened from the header.
- There must be no fixed mobile bottom navigation.
- Header must keep the current surface clear and provide the sidebar trigger.
- Main content must use semantic `<main>` inside `SidebarInset`.
- Sidebar identity must remain lean: LocalSpeak, "IELTS speaking practice" or equivalent concise subtitle, grouped navigation, and a small footer/status area only.
- Do not include coach-heavy widgets in the sidebar.
- Do not include hero dashboard quick stats in the app shell.
- Do not duplicate complete desktop and mobile content trees.

## Navigation Contract

Navigation must be config-driven and route-ready, even if Phase 07.1 keeps client-side surface switching to preserve current state.

### Required Navigation Items

| Group | Label | Status | Behavior |
|-------|-------|--------|----------|
| Practice | JSON Analysis | Enabled | Switches to JSON Analysis surface |
| Practice | Live Audio Practice | Enabled | Switches to Live Audio Practice surface |
| Coming soon | IELTS Practice | Disabled | Shows coming-soon badge/copy; no surface implementation |
| Coming soon | TOEIC Practice | Disabled | Shows coming-soon badge/copy; no surface implementation |

### Navigation Interaction Rules

- Enabled items use `SidebarMenuButton`.
- Active item uses shadcn active state plus restrained accent.
- Disabled items must not navigate, must not appear as primary calls to action, must be marked `Coming soon`, and must remain readable in collapsed/tooltip state.
- Mobile navigation uses the same Sidebar configuration through the drawer.
- Collapsed desktop sidebar must preserve accessible labels through tooltip or visible text according to shadcn Sidebar behavior.

## JSON Analysis Contract

JSON Analysis must preserve existing behavior:

- Paste JSON.
- Upload `.json`.
- Load sample.
- Clear.
- Syntax parse.
- Debounced backend preview.
- Accepted-for-analysis gate.
- Analyze request.
- Warnings.
- Result tabs.
- AI feedback request/retry.
- Saved-session save/list/reopen.
- Stale result behavior.
- Contract parsing via Zod.

### JSON Before Results

Order:

1. Surface header.
2. JSON input card.
3. Sample/upload/clear controls.
4. Validation preview card.
5. Analyze button and disabled guidance.

Rules:

- Primary action is `Analyze Pronunciation`.
- The Analyze button is disabled until backend validation accepts the JSON.
- Disabled helper text must explain the next step.
- Upload and sample controls are secondary outline buttons.
- The JSON textarea must have a persistent label: `Speech assessment JSON input`.
- Validation preview must be visible before analysis.
- No hero overview or quick-stat cards before input.

### JSON Loading State

Show:

- Skeleton result placeholder.
- `aria-live="polite"` status.
- Copy: `Computing deterministic pronunciation and fluency metrics...`

Do not hide the current input unexpectedly, move primary loading feedback below the fold on phone, or show decorative loaders without text.

### JSON Error State

Use shadcn `Alert` or product `StatePanel`.

Required copy:

> We couldn't analyze this JSON. Check the validation preview, then try Analyze Pronunciation again.

Rules:

- Keep JSON input available.
- Keep validation preview visible.
- Error must include problem and solution path.
- Do not use destructive red for non-destructive validation warnings unless analysis truly failed.

### JSON After Results

Order must be:

1. Priority action.
2. Metric summary.
3. Evidence tabs.
4. Saved history.
5. Collapsed JSON input.

#### 1. Priority Action

- Heading: `What should I practice next?`
- Use existing `derivePracticePriority` behavior.
- Priority card must be high-contrast but not premium/hero styled.
- Include one secondary link/action to review evidence.

#### 2. Metric Summary

- Show pronunciation band/score, fluency band, WPM, pause ratio or equivalent existing metrics.
- Use product `MetricCard` composed from shadcn Card.
- Cards must wrap to one column on phone.

#### 3. Evidence Tabs

Use shadcn/Radix Tabs.

Required tabs preserve existing evidence areas:

- Pause Analysis.
- Words.
- Phonemes.
- IELTS / AI Analysis.

Rules:

- Tabs must keep `tablist`, `tab`, and `tabpanel` semantics.
- Keyboard arrow navigation must continue to work.
- Evidence cards must be compact and scannable.
- Word chips must wrap and never create horizontal overflow.
- AI feedback is secondary/opt-in, not primary.

#### 4. Saved History

- Saved sessions are secondary.
- Place below evidence/result area.
- Must not compete visually with current result.
- Save/reopen remains discoverable.
- Reopened result marker must be visible but subtle.

#### 5. Collapsed JSON Input

- After successful analysis, input collapses.
- Trigger copy: `Change JSON input` / `Hide JSON input`.
- If input changes after results, show stale notice: `Input changed. Analyze again to update these results.`

## Live Audio Practice Contract

Live Audio must preserve existing behavior:

- Reference text input.
- Record disabled until reference text exists.
- Connecting state.
- Recording state.
- Stop recording.
- Live transcript display.
- Pronunciation scoring after completion.
- Existing `useDeepgramSession` session behavior.
- Existing `scorePronunciation` behavior.

### Audio Surface Thesis

Live Audio is a focused sentence-practice flow, not an exam cockpit.

Required order:

1. Reference text.
2. Readiness guidance.
3. Recording control.
4. Live transcript.
5. Pronunciation score.

### Audio Idle / No Reference State

Show:

- Reference sentence card.
- Label: `Reference sentence`.
- Input placeholder: `Enter one sentence you want to practice.`
- Readiness card explaining that recording is disabled.
- Disabled recording control.

Required copy:

> Enter one sentence first. Recording stays disabled until LocalSpeak knows what you want to practice.

### Audio Ready State

When reference text exists and not recording:

- Primary CTA: `Start Recording`.
- Status badge: `Ready`.
- Readiness guidance visible.
- Transcript panel empty state visible.

Required copy:

> Read the sentence once, then record one focused attempt.

### Audio Connecting State

Show:

- Disabled primary button.
- Status badge: `Connecting`.
- Progress or indeterminate visual.
- Copy: `Connecting to live transcription...`

### Audio Recording State

Show:

- Prominent recording control card.
- CTA: `Stop Recording`.
- Status badge: `Recording`.
- Waveform or Progress area.
- Live transcript panel below recording control.

Rules:

- Recording control uses shadcn-composed `Card`, `Button`, `Badge`, and `Progress`.
- Waveform is supportive, not required to be exact audio metering if existing behavior is preserved.
- Button remains visible at 390px without scrolling horizontally.
- Active recording status must be clear visually and textually.

### Audio Transcript State

Transcript panel:

- Empty copy: `Your live transcript will appear here.`
- Streaming text updates in an `aria-live` region.
- Interim/final transcript can use existing display behavior.
- Do not use `dangerouslySetInnerHTML`.

### Audio Error State

Use `Alert` or product `StatePanel`.

Required copy:

> We couldn't start recording. Check microphone permission and try again.

Rules:

- Keep reference text.
- Keep retry path visible.
- Do not clear transcript unless existing behavior requires it.

### Audio Complete / Result State

Show:

- Pronunciation result card.
- Overall score out of 100.
- Word-level chips.
- WPM, pause count, duration.
- Summary feedback.

Rules:

- Score colors: success for good, warning for okay, destructive/danger for weak/missed.
- Word chips must wrap and stay within container.
- Result appears after transcript, unless a desktop aside is used and remains stable.

### Audio Layout

Default:

- Single-column layout.

Desktop optional:

- A modest aside is allowed only at `lg` and above.
- Aside may contain readiness and/or result summary.
- Aside must not duplicate primary controls.
- Phone must remain single-column.

## Responsive Contract

### Desktop: `>= 1024px`

- Sidebar visible using shadcn Sidebar.
- Main content inside `SidebarInset`.
- Workspace max width may be constrained for readability, but content must not look like a centered landing page.
- JSON evidence and metrics may use responsive grids.
- Audio may use optional modest aside only if stable.

### Tablet: `768px-1023px`

- Sidebar may be collapsed or drawer-based according to shadcn behavior.
- Header remains visible.
- Content uses 24px padding.
- Metric cards may be two-column if no overflow.
- Evidence tabs must remain usable without clipped labels.

### Phone: `390px` baseline

Hard requirements:

- No horizontal overflow.
- No hidden primary actions.
- No fixed bottom nav.
- Sidebar opens from header trigger as mobile drawer.
- Content padding: 16px.
- Cards use one-column stacking.
- Buttons wrap or become full-width where needed.
- Tab lists scroll horizontally only if shadcn semantics remain intact and no page overflow is introduced.
- Word chips wrap.
- JSON textarea width is `100%` / `min-w-0`.
- Recording button remains visible and at least 44px tall.
- Disabled coming-soon nav entries remain readable.

## Accessibility Contract

### Landmarks and Semantics

- Use a single app-level `<main>` inside `SidebarInset`.
- Sidebar nav has an accessible label.
- Each surface has one clear page heading.
- JSON Analysis and Live Audio sections use semantic headings in order.
- Do not duplicate full content trees for desktop/mobile.

### Keyboard Navigation

Must support:

- Tab to sidebar trigger.
- Open/close mobile drawer by keyboard.
- Navigate enabled sidebar items by keyboard.
- Skip disabled future entries or expose them as disabled non-actions.
- Operate Tabs using Radix/shadcn keyboard behavior.
- Focus JSON textarea, upload, sample, clear, and Analyze.
- Focus audio reference input and recording control.

### Focus States

- All interactive elements use visible focus rings.
- Focus rings must have sufficient contrast on neutral surfaces.
- Do not remove shadcn focus-visible styles.

### Labels

Required accessible names:

- `Speech assessment JSON input`.
- `Upload .json file`.
- `Analyze Pronunciation`.
- `Reference sentence`.
- `Start Recording`.
- `Stop Recording`.
- Sidebar trigger must have an accessible label from shadcn or explicit copy.

### Touch Targets

- Minimum interactive target: 44px high/wide where practical.
- Icon-only controls must be 44px minimum with accessible label.
- Sidebar mobile drawer controls must be reachable by thumb without relying on bottom nav.

### Contrast

- Body text on background/cards must meet WCAG AA.
- Muted text must remain readable.
- Accent text must not be used on low-contrast tinted backgrounds.
- Disabled future nav entries must appear disabled but still readable.

### Screen Reader State

Use `aria-live="polite"` for:

- JSON validation/loading.
- JSON analysis loading/error.
- Audio connecting/recording status.
- Live transcript updates where appropriate.
