## Global Implementation Patterns

### shadcn primitive pattern

Generated primitives under `apps/web/components/ui/*` should follow existing shadcn style:

- Import `cn` from `@/lib/utils`.
- Export small component functions.
- Preserve Radix/shadcn semantics and data attributes.
- Do not place LocalSpeak product behavior inside `components/ui`.
- Do not add feature-specific hex colors to primitives.

### Client state pattern

Existing JSON/audio behavior is already isolated in client components. Phase 07.1 should recompose UI without rewriting data flow:

- Keep JSON preview/analyze/sample/clear/AI/saved-session behavior in `JsonAnalysisPanel`.
- Keep audio session behavior in `AudioModePanel`, `useDeepgramSession`, `RecordButton`, `LiveAnalysisPanel`, and `scorePronunciation`.
- Move app-shell state into `LocalSpeakWorkspace` with a `SurfaceId` state.
- Keep one mounted JSON surface and one mounted Audio surface; hide inactive surfaces with `hidden`/`aria-hidden` rather than duplicating desktop/mobile content trees.

### Contract parsing and API pattern

All API calls parse shared Zod contracts from `@localspeak/contracts` and surface safe user-facing errors:

- `/api/json-analysis/preview` -> `JsonAnalysisPreviewResponseSchema`.
- `/api/json-analysis/analyze` -> `JsonAnalysisResponseSchema`.
- `/api/json-analysis/sample` -> `JsonAnalysisSampleResponseSchema`.
- `/api/gemini-feedback` -> `GeminiFeedbackResponseSchema`.
- Saved sessions preserve explicit owner-key save/list/reopen behavior.

## App Shell Patterns

### `apps/web/app/page.tsx`

Target pattern:

```tsx
import { LocalSpeakWorkspace } from "@/components/app-shell/local-speak-workspace";

export default function Home() {
  return <LocalSpeakWorkspace />;
}
```

Do not keep shell logic, local nav components, radial backgrounds, or hero stats in `app/page.tsx`.

### `apps/web/components/app-shell/nav-config.ts`

Target pattern:

```tsx
export type SurfaceId = "json" | "audio" | "ielts-practice" | "toeic-practice";

export type NavItem = {
  id: SurfaceId;
  label: string;
  description: string;
  group: "Practice" | "Coming soon";
  enabled: boolean;
  badge?: string;
  icon: React.ComponentType<{ className?: string }>;
};
```

Required entries:

- `json` -> "JSON Analysis", enabled.
- `audio` -> "Live Audio Practice", enabled.
- `ielts-practice` -> "IELTS Practice", disabled, `Coming soon`.
- `toeic-practice` -> "TOEIC Practice", disabled, `Coming soon`.

### `apps/web/components/app-shell/local-speak-workspace.tsx`

Target pattern:

```tsx
"use client";

export function LocalSpeakWorkspace() {
  const [activeSurface, setActiveSurface] = useState<SurfaceId>("json");

  return (
    <SidebarProvider>
      <AppSidebar activeSurface={activeSurface} onSurfaceChange={setActiveSurface} />
      <SidebarInset>
        <AppHeader activeSurface={activeSurface} />
        <main className="min-w-0 flex-1 p-4 md:p-6">
          <SurfaceRenderer activeSurface={activeSurface} />
        </main>
      </SidebarInset>
    </SidebarProvider>
  );
}
```

Required behavior:

- Desktop uses shadcn Sidebar.
- Phone opens shadcn Sidebar drawer from header trigger.
- No fixed bottom nav.
- No custom `NavItem`/`BottomNavItem`.
- Main content uses one semantic `<main>`.

### `apps/web/components/app-shell/app-sidebar.tsx`

Use shadcn Sidebar composition:

- `Sidebar`
- `SidebarHeader`
- `SidebarContent`
- `SidebarGroup`
- `SidebarGroupLabel`
- `SidebarGroupContent`
- `SidebarMenu`
- `SidebarMenuItem`
- `SidebarMenuButton`
- `SidebarFooter`
- `SidebarRail`

Implementation rules:

- Enabled items call `onSurfaceChange(item.id)`.
- Active items use `SidebarMenuButton isActive`.
- Disabled future items do not navigate and expose "Coming soon" visibly or via Badge/Tooltip.
- Sidebar identity is lean: LocalSpeak + "IELTS speaking practice" + grouped nav + small footer/status.
- Avoid coach-heavy widgets and hero stats.

### `apps/web/components/app-shell/app-header.tsx`

Target elements:

- `SidebarTrigger`
- `Separator`
- `Breadcrumb` or current surface title
- Optional concise state text

Header must not become a marketing hero. It should identify the active surface and provide mobile drawer access.

### `apps/web/components/app-shell/surface-renderer.tsx`

Preserve mounted-state behavior:

```tsx
<section hidden={activeSurface !== "json"} aria-hidden={activeSurface !== "json"}>
  <JsonAnalysisView />
</section>
<section hidden={activeSurface !== "audio"} aria-hidden={activeSurface !== "audio"}>
  <AudioPracticeView />
</section>
```

Future disabled surfaces should not render real question-bank/practice functionality in Phase 07.1.

## Design System Patterns

### `apps/web/app/globals.css`

Refine tokens toward UI-SPEC values:

- light neutral background and surfaces
- restrained blue accent
- success/warning/destructive semantic colors
- system sans typography
- no `font-display`/serif product heading treatment
- no radial-gradient frame variables or one-off feature colors

Keep global CSS to Tailwind imports, theme tokens, and resets only. Do not add component-level CSS.

### Product-level components

Create composed product components outside `components/ui`:

- `action-banner.tsx` for non-hero priority/action surfaces.
- `metric-card.tsx` for summary metrics.
- `state-panel.tsx` for warning/error/loading/empty states.
- `evidence-card.tsx` for compact evidence sections.
- `recording-control.tsx` for audio recording card.
- `practice-readiness-card.tsx` for audio guidance/readiness.

Each card should have one job, use neutral borders/surfaces, and avoid premium floating hero treatment.

## JSON Analysis Patterns

### Preserve behavior in `JsonAnalysisPanel`

Keep these exact behavior owners and flows:

- `derivePracticePriority` chooses the next practice action from weak phoneme, longest pause, weak words, or fluency summary.
- `parseJson` handles empty/invalid/parseable syntax.
- Debounced preview calls `/api/json-analysis/preview`.
- Analyze calls `/api/json-analysis/analyze`.
- Sample calls `/api/json-analysis/sample`.
- AI feedback calls `/api/gemini-feedback`.
- Reopened saved session sets analysis result and marker without recomputing.
- Results become stale when input changes after a completed analysis.

### Target information architecture

Before results:

1. Surface header.
2. JSON input card.
3. Sample/upload/clear controls.
4. Validation preview.
5. `Analyze Pronunciation` CTA and disabled guidance.

After results:

1. Priority action.
2. Metric summary.
3. Evidence tabs.
4. Saved history.
5. Collapsed JSON input.

Required copy/selectors:

- `Speech assessment JSON input`
- `Analyze Pronunciation`
- `What should I practice next?`
- `Review the evidence`
- `Saved sessions`
- `Change JSON input`
- `Hide JSON input`
- `Input changed. Analyze again to update these results.`

### Tabs/evidence pattern

Use shadcn/Radix Tabs. Preserve:

- `tablist`, `tab`, `tabpanel` semantics.
- Keyboard arrow behavior.
- Pause Analysis / Words / Phonemes / IELTS or AI Analysis evidence areas.
- Word chip wrapping at 390px.
- AI feedback as opt-in/secondary.

## Live Audio Patterns

### Preserve behavior in `AudioModePanel`

Keep:

- `referenceText` state.
- `useDeepgramSession(referenceText)` call.
- record disabled until `referenceText.trim()` exists.
- `start`/`stop` handlers.
- transcript display text combining final/interim transcript.
- `scorePronunciation(transcript.words, referenceText)` after complete.

### Target information architecture

Live Audio is a focused sentence-practice flow:

1. Reference text.
2. Readiness guidance.
3. Recording control.
4. Live transcript.
5. Pronunciation score.

Required copy/selectors:

- `Reference sentence`
- `Enter one sentence first. Recording stays disabled until LocalSpeak knows what you want to practice.`
- `Start Recording`
- `Stop Recording`
- `Connecting to live transcription...`
- `Recording now. Speak clearly and finish the full sentence.`
- `Your live transcript will appear here.`
- `Pronunciation result`

### Recording control pattern

Recompose `RecordButton` behavior into a product `RecordingControl` using shadcn:

- `Card`
- `Button`
- `Badge`
- `Progress` or existing waveform visual

The visualizer is supportive only; do not rewrite streaming/audio logic to chase exact metering.

## Anti-Patterns to Remove

Do not reuse:

- `NavItem` custom desktop nav.
- `BottomNavItem` fixed mobile nav.
- `QuickStat` hero stats.
- radial-gradient page background.
- warm serif premium typography.
- `font-display` Instrument Serif heading treatment.
- "Premium pronunciation coach" positioning.
- large landing-style hero overview.
- coach-heavy sidebar widgets.
- duplicate responsive content trees.
- one-off hex colors inside feature components.
- custom tab buttons.
- custom primitive record button classes.
- custom warning/error cards where shadcn Alert/product StatePanel should be used.
